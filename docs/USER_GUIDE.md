# SHORTLIST 使用指南

这份指南按每天真正使用的顺序说明操作。系统只提供研究、模拟和提醒；真实买卖由你在券商端决定和执行。

## 1. 安装与启动

需要 macOS、Python 3.10 或更高版本。

```sh
git clone https://github.com/zc6503204-collab/stock-strategy-dashboard.git
cd stock-strategy-dashboard
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
./start.command
```

页面地址为 `http://127.0.0.1:8765/`。服务只在本机开放。

如需登录后自动运行和 Mac 通知：

```sh
.venv/bin/python scripts/install_background.py
```

安装后在 macOS“系统设置 → 通知”中检查 SHORTLIST 的通知权限。休眠、关机、断网或退出登录期间无法持续盯盘；恢复后程序会先补齐数据并取消过期计划。

## 2. 连接行情

进入“系统状态”，逐项确认连接、权限和最近数据时间。

### 长桥

长桥承担策略使用的主行情。按照页面提示完成本机 OAuth 授权，再分别确认 A股、美股、K线和盘口权限。App 中可见行情不代表 OpenAPI 具有相同权限。

### 国泰海通灵犀

灵犀保留为手动补充查询；A股自动发现改由长桥分页证券库驱动：

```sh
python3 scripts/install_lingxi.py
```

把你自己的 `gtht-entry.json` 放在安装脚本创建的 `.local/vendor/gtht/gtht-skill-shared/`。不要把它复制到 `docs/`、截图、Issue 或提交中。

### 盈透 IBKR

启动 TWS 或 IB Gateway，开启 API 并设置为只读。在“系统状态”中填写本机连接参数并测试。系统只在逐标的权限和数据口径核验通过后，把盈透用于美股核验或备用。

## 3. 每天盘前怎样选股

切换到“A股工作区”或“美股工作区”，进入“盘前观察”。

### A股

无需每天手动启动。电脑开机联网、本地服务运行且行情授权有效时，程序按以下时点自动工作：

| 时点 | 工作 |
|---|---|
| 9:10 | 分页更新证券库，重新检查当天策略资格 |
| 9:20 | 发布盘前计划；未完成时显示覆盖进度，完成后补充 |
| 盘中每5分钟 | 读取完整支持范围报价与缓存日线，重新发现池内外候选 |
| 盘中每30分钟 | 重新复核完整日线资格，并继续补齐缺失历史 |
| 每根完整5分钟K线后 | 验证形态、失效条件与监测排序；不使用未完成K线确认买点 |
| 15:05起 | 补齐当日日线，缓存供下一交易日使用 |
| 15:10 | 保存收盘日报及下一日跟踪安排 |

证券库分页成功不等于策略研究完成。首页分别显示供应商证券数、支持范围、日线覆盖、报价覆盖、分钟验证覆盖、执行覆盖及缺失数。科创板、北交所不在首版支持范围。首次日线预热可能持续数小时或跨时段；中断后使用缓存续跑，分页失败会保存进度，重复或总数变化则重新枚举。上一轮未完成会合并调度，不堆积任务。手动刷新只用于补充。

研究池最多展示80只，重点实时监测最多12只；两个上限都不限制全范围发现。池外满足条件的股票也会进入独立分钟验证队列，按形态阶段、等待时长等安排检查，验证后可入池并替换旧股票。榜单只是补充线索。查看“分钟验证排队数量”和“最久等待时间”，可以区分“尚未轮到验证”和“已经检查但条件不通过”。

旧候选没有每日自动保留资格。结构失效立即撤销，数据异常暂停买点但保留持仓退出监测。普通监测候选被更高优先级候选直接替换，或被同级且连续两轮领先至少5分的候选替换。相同名单必须来自重新检查，变化历史会记录通过条件和退出原因。

首页显示实际运行记录是否达到两个完整交易日。本轮真实连续运行验收仍待积累，不能根据测试通过或页面能够打开就宣布完成。

### 美股

长桥每天从美股全市场筛选最多80只候选，再用相同的本地日线规则复核和行业软分散。盈透在行情权限验证后承担核验和备用。美股与A股的资金、基准、交易时间和策略参数完全分开。

### 准备度怎么看

准备度只回答“明天或今天盘中值得先看谁”。它不代表买点已经成立，也不是历史胜率。点击候选可以查看：

- 它由哪些策略选入；
- 日线趋势和相对强弱；
- 突破观察位与保护参考；
- 仍缺少的盘中条件。

## 4. 盘中怎样确认

系统自动分配最多12个重点实时名额，首页突出最多3只；也可以手动固定。持仓、仍有效的执行计划和手动固定股票优先，首页说明保护名额的占用和缺口。池外股票的分钟验证不需要先占这12个名额。默认不读取真实账户；手工录入不会开启券商账户读取或同步，只有明确点击券商同步才会开启。

行情推送优先，盘口推送配合轮询补充，历史查询和全范围扫描与实时处理分离。每个策略独立显示预热条件；趋势EMA可用前一交易日连续完整分钟线预热，不必每天等到11:15。14日同时间量能只约束需要该条件的突破类策略。系统会继续检查：

- 指数趋势、盘中VWAP、全范围上涨占比和行情覆盖是否通过；
- 行业3日、5日相对强度、前30%排名及数据覆盖是否通过；
- 股票的策略结构与公告目录风险筛查是否通过；
- 同时间成交量是否达标；
- 行情和盘口是否足够新；
- 按0.01元价格单位计入滑点和费用后是否还有可成交区间，净收益风险比是否至少1.5；
- 现金、手数、风险预算和持仓名额是否允许。

只要一项不通过，“今日决策”就说明原因；区间为空不会通过放宽止损或抬高目标来制造买点。报价需在30秒内，盘口需在15秒内；全范围发现使用的较宽时间窗口不代替这一执行标准。

计划卡同时显示买入区间、结构止损、第一目标、剩余仓位退出方法、数量、时间和仍未满足的条件。状态含义如下：

| 状态 | 含义 |
|---|---|
| 观察 | 尚未形成完整交易形态 |
| 等待触发 | 结构仍可跟踪，但上一买点已过期或尚需新确认 |
| 执行核验 | 形态已触发，仍需市场、行业、公告、报价、盘口和成本检查 |
| 当前可买 | 当前5分钟信号及已实现检查均通过；仍是试运行规则 |
| 已买入 | 已手工登记实际成交，按原计划跟踪退出 |
| 已失效 | 结构或入场区间失效，停止作为买入计划 |
| 已过期 | 当日结构计划已到期 |
| 待恢复 | 行情、服务或必要数据中断，暂停买入判断 |

**A股14:45为结构计划最晚入场时间，单次买点仍只有5分钟有效期。** 不能因为计划卡仍在，就沿用早已过期的买点。恢复服务后也不补发过期买点通知。

目前市场检查是明确的程序规则，不等于完整情绪状态机；行业检查使用当前分类，不代表历史成分。公告只做近30日目录规则筛查：接口缺失、目录截断或重大事项命中会暂停买入。没有命中不代表已经完成公告全文或重大事项实质核验，因此页面不会给出完整A股评级或宣称高胜率。

## 5. 单股分析

进入“单股分析”，输入股票名称或标准代码，例如：

- `600206.SH`
- `300750.SZ`
- `AAPL.US`

默认分析是一次即时快照，不占监测名额。页面会列出日线数量、今日完整5分钟K线、历史同时间样本、基准和盘口状态，再逐策略说明“符合、等待或不适用”。数据不完整时仍显示可可靠计算的趋势和关键位，但不会给出买入结论。

点击“加入盘中监测”后才会持续刷新。临时填写成本和数量不会写入数据库；只有点击“保存为真实持仓”才进入持仓管理。

## 6. 真实持仓怎样盯盘

真实买入后，点击计划卡的“登记已实际买入”，或到“持仓管理”手工录入。这里记录你已经完成的交易，不会向券商下单。至少核对：

- 股票代码、成交数量和实际成本；
- 实际买入时间或日期，以及买入费用；
- 初始保护价；
- 第一止盈参考。

从计划登记会保留原计划、策略版本和成本；偏离原买入区间的实际成交仍可如实记账，并标明偏差。手动记录与券商持仓同步独立，记录买卖不会打开账户读取。需要券商核对时，再单独使用只读同步。

实际分批卖出后点击“登记实际卖出”，填写数量、成交价、成交时间和费用。系统扣减剩余股数、分摊买入费用并记录已实现净盈亏；全部卖出保留历史。相同成交编号重复提交不会重复扣仓。A股会检查T+1可卖数量，缺少买入日期时先补齐资料。

首页优先显示需要处理的持仓，完整列表在持仓页。短线第3个交易日、VCP第10个交易日最晚于14:50进入到期退出处理。分批卖出后按完整K线抬高剩余仓位保护线；初始保护价不向亏损方向放宽。A股当日新买股份即使触及止损，也只记录“T+1暂时无法卖出”，不会伪造成交。

提醒表示条件已触发，不等于券商已经成交。跳空、停牌、涨跌停和流动性不足时，止损价可能无法成交。

## 7. 策略参数与复盘

“策略中心”按日内、短线和波段展示策略。A股与美股参数独立保存。每次修改都会生成新版本：

- 旧版未成交信号取消；
- 已有持仓继续使用入场时的规则；
- 新版前向样本从零开始；
- 历史版本可以回滚，但回滚也会生成一个新版本。

“复盘研究”提供三种口径：

1. **策略影子模拟**：每条有效信号独立模拟，用于看策略本身。
2. **组合模拟**：执行资金竞争、同股合并和持仓上限，用于看实际组合效果。
3. **历史探索**：用与实时一致的研究引擎逐时点重放技术信号。缺少当时市场、行业、公告、风险标记或盘口时显示“数据不足”，不计算收益；当前接口不把技术信号数量当成成交或盈利。

手工实际成交另外保存，不混入模拟胜率。结束的前向交易不足30笔时只显示“样本不足”；达到30笔后才作初步比较，达到100笔的界面标签仍不表示已经证明策略有效。应同时看成交率、胜率区间、平均盈利和亏损、成本后期望、回撤及数据覆盖，不能只比较胜率。

| 内容 | 默认频率 |
|---|---|
| A股证券范围与每日资格 | 盘前更新范围，盘中每30分钟完整资格复核 |
| A股全范围发现与研究池替换 | 盘中每5分钟调度，未完成时显示延迟 |
| 池内外分钟形态验证 | 独立排队，既看机会优先级也看等待时长 |
| 美股每日核心池 | 每个交易日盘前一次，也可手工强制重跑 |
| 重点股票行情 | 推送优先，15秒查询补充 |
| 买点确认 | 每根完整5分钟K线结束后 |
| 止损、止盈触价 | 有效实时行情到达时 |

同一交易日已取得的完整日线会复用本机缓存，但所有评分会重新计算。低成交股票最后成交时间较旧，不会单凭这一点判断连接故障。

## 9. 常见问题

### 怎样使用 GPT 选股工作台

打开“GPT 选股”后按四步完成：先选择自动、盘前、盘中或单股模式；生成并预览研究任务；复制到 ChatGPT，在 ChatGPT 内确认 `@longbridge` 调用；最后把整段答案粘回看板。本地附带的最多20只量化候选只是 Longbridge 工具不可用时的后备，不是全市场扫描结果。GPT最终可以选择本地池外股票，但只能返回0–3只。

答案末尾必须包含 `SHORTLIST_RESULT_V1` 结构化 JSON。看板只解析这个标记内的数据，不执行回答中的HTML、链接、脚本或操作指令。字段、市场、交易日、研究包、时间或股票代码不一致时会显示“需要修正”，原文仍留在输入框中，但不会激活候选。

合法导入后，本机会重新读取证券名称、行情、日线与盘口。GPT说“买”仍可能显示“GPT精选·等确认”；只有本地实时价格、盘口、有效信号、不追价线、失效线、风险名额和A股限制全部通过，才会显示“当前可考虑买入”。GPT与本地仓位上限取较小值。收盘后本轮失效，完整问答和账户上下文会清除。

本功能不调用 OpenAI API，也不能后台读取你在 ChatGPT 内连接的 App。账户选项每次默认关闭；只有当次主动勾选，才会把长桥和盈透的脱敏摘要及最多40只持仓写入任务。可选的研究对话链接只接受 `https://chatgpt.com` 地址并保存在本机。平台不会猜测 App 连接状态，也不会提供下单、改单、撤单或最大可买量工具。

### 页面能打开，但没有买入股票

先看“现在为什么不买”及三层覆盖。常见原因是分钟验证尚在排队、休市、盘口缺失、报价过期、某策略量能基线不足、行业覆盖不足、公告待核验、成本后没有可成交区间或风险名额已满。系统允许没有推荐，不会为了填满卡片而把观察股包装成买点。

### 单股分析显示部分数据

“部分数据”通常表示已有日线或K线，但还缺基准、盘口或同时间量能。趋势判断仍可展示；严格买点会被统一风控否决。加入监测后程序会继续预热。

### 盘前显示很多初筛股票，最后只有10只

证券范围、研究池和页面摘要是不同数量。研究池最多80只，盘前页摘要最多10只，首页突出最多3只；12个实时名额不限制全范围发现和池外分钟验证。先看覆盖和排队情况，再区分数据未检查与策略条件不通过。

### 浏览器关掉后还会提醒吗

安装后台服务后会。浏览器只是界面；本机行情和提醒服务独立运行。Mac进入休眠或断网时无法继续。

### 日常盯盘是否消耗 Codex 额度

不消耗。日常计算和通知由本机规则引擎完成。只有你主动让 AI 研究、解释或修改策略时，才会使用相应服务额度。

## 自动研究记录与统计

“复盘”展示盘前计划、日报、版本化策略的成交率、胜率、平均盈亏、成本后净收益和回撤；1—3日短线与5—10日波段分别比较。只有模拟成交形成盈亏，观察股票后来上涨不会计入。没有成交时，日报列出信号数量、执行阻断与数据缺口。

研究链路按“市场 → 板块 → 个股 → Setup → 买点 → 风险”显示。已实现指数/广度、行业持续性和公告目录检查；完整情绪状态机、公告全文与重大事项实质判断仍有缺口，准备度不能替代完整交易评级。S04强势首次缩量回踩与VCP以试运行版本比较；S05右侧修复仍是未激活研究卡。

只读接口：

- `/api/state`：扫描覆盖、运行时间、候选变化和监测名额。
- `/api/research/days?market=CN&date=YYYY-MM-DD`：每日批次和报告。
- `/api/research/candidates/600519.SH`：个股逐轮检查与变化历史。
- `/api/research/comparison?market=CN`：策略版本、周期和模拟比较。
- `/api/plans?market=CN&history=true`：计划列表，包含失效、过期计划；关注 `state`、`reason`、`strategy_version`、`entry_min/max`、`stop`、`target`、`net_rr`、`valid_until` 和 `signal_valid_until`。
- `/api/plans/{plan_id}`：单计划与版本变化历史。
- `/api/real-holdings/history`：本地手工实际成交与剩余持仓记录。

`/api/state` 的 `auto_research.discovery` 区分 `quote_coverage`、`signal_coverage`、`execution_coverage`，并提供 `validation_backlog` 和 `oldest_wait_seconds`。计划状态不能替代有效期、研究链和报价时间的联合核验。

以下接口只修改本机记录，写入时需要本地请求头 `X-Dashboard-Local: 1`，不调用券商交易接口：

| 接口 | 最低字段及含义 |
|---|---|
| `POST /api/plans/{plan_id}/confirm-buy` | `quantity`、`cost`；实际成交还应填 `entry_time`（含时区）或 `entry_date`，可填 `entry_fee`、`note`。返回 `holding` |
| `POST /api/real-holdings/sell` | `id`（持仓编号）、`quantity`、`price`、`sold_at`（含时区）；可填 `fee`、`execution_id`、`note`。返回更新后的 `row` |
